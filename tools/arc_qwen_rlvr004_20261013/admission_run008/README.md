This is a new offline bridge from the independently reviewed run008 source
proposal to a numeric publication candidate. It does not call Kaggle, inspect
credentials, allocate provider versions, mint a real session epoch, import a
model, execute a scorer, or semantically read evaluator archives. The lead is
the sole publisher. The original run007 failed source, clocks, proofs and charges
remain historical evidence.

## Stages and authority

1. The sole publisher supplies the actual official terminal notebook/code
   bracket. `seal_inputs.py` verifies its six raw readbacks against the original
   hashes and creates a closed native observation. It preserves the original
   observation and every raw body byte-for-byte; this is not another provider
   read. The original owner direction is copied unchanged, including its
   continuing monitor/retrieval and distinct-reviewed-next-iteration scope.
2. `assemble.py --mode proposal` derives unreserved numeric successors from
   that bracket and builds inert source/notebooks with no epoch. The complete
   `ADMISSION-PROPOSAL.json` binds the exact assembler, source, deployment,
   collector, observation, owner direction, solver and preserved escrow hashes.
3. An independent reviewer supplies a new namespace PASS, runtime PASS and
   material APPROVED receipt for that exact proposal. The assembler cannot
   generate these approvals. `--mode final` requires all three path/hash pairs
   and exact equality with the independently reviewed proposal. Historical
   approval schemas are rejected; GPU validation is explicitly still false.
4. The resulting source-admitted candidate still requires the separate native
   publisher/config/action review. Publish only its `code-payload`, retrieve the
   exact numeric Dataset version, then execute `accept_numeric_mount.py` against
   the authentic numeric readback receipt and downloaded bytes. This wrapper
   retains the original helper/owned-process checks and exact archive/manifest/
   runtime hashes. It produces no GPU or scientific success claim.
5. Save and read back the inert numeric notebook source, settings and input
   identities. Only after those gates does the sole publisher supply the one
   real predispatch epoch to the unchanged pure finalizer and review/send the
   exact active wire. Its maximum dispatch age remains60 seconds and the
   immutable inner/outer/provider/absolute offsets remain42000/42180/42300/43200.
   Pure deterministic byte finalization alone is never provider authority.
6. The current owner scope includes terminal monitoring and exact retrieval.
   A new candidate after a demonstrated failure needs fresh analysis, distinct
   identity and review; there is no blind same-candidate automatic resubmission.

The candidate includes historical lineage and target-free solver material for
local review. These files and operational state are not upload roots or public
Git payloads. Public Git receives only code/tests/documentation/sanitized review
summaries. No successful baseline follows from assembly or provider acceptance.

## Interfaces

Read `assemble.py --help` for exact required paths. All outputs must be fresh
paths below `.irisx/run008-admission`. Source proposal is the frozen
`independent-reviewed-proposal`; base is the byte-identical reconstructed run007
candidate, with its authentic `source-rebuild` sibling containing the original
target-free solver descriptor. Every original is read-only.

The namespace receipt format is `irisx/run008-solver-namespace-review-v1`, with
status PASS; integer path_substitutions2; reverse_byte_equality true;
escrow_bodies_read false; original_solver and projected_solver `{bytes,sha256}`;
unchanged dataset_escrow_sha256; and the exact source_proposal_inventory_sha256.

The runtime receipt format is `irisx/run008-runtime-review-v1`, status PASS.
The material receipt format is `owned-rl-reviewed-material-v1`, status APPROVED.
Both bind proposal_sha256 and every `BINDING_KEYS` field from `assemble.py`, plus
namespace receipt hash, baseline_unchanged_members199 and
production_GPU_validation_passed false. Material also binds the runtime receipt
hash and retains the historical null dataset_content_sha256; no evaluator read
is performed to manufacture a semantic commitment.

The numeric mount wrapper takes candidate-root, code-root, code-receipt-path,
code-receipt-sha, output-root, manifest-sha and inventory-sha. It retains numeric
Dataset identity/privacy/before-after/readback-layout/inventory checks and runs
the unchanged no-model helper inside the actual owned process guard, including
bounded logs, timeout, cleanup and complete unforced closure for acceptance.
The new result format is `irisx/run008-owned-numeric-mount-acceptance-v1`.
