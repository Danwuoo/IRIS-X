# 下一代智能體：設計構想與理論

---

## 0. 壓縮命題

下一代智能體不應只被定義為「能回答問題的模型」，而應被定義為：

> **能在有限 context、有限資源與不完全資訊下，形成假設、規劃行動、執行操作、收集證據、驗證結果、提交狀態、管理記憶、定位失敗並恢復路徑的可學習智能系統。**

換言之，智能體的核心不只是 **reasoning**，而是：

```text
think -> plan -> act -> observe -> verify -> commit / rollback -> remember -> recover
```

這不是一條固定流程，而是一個由 learned control 驅動、可觀測、可審計、可訓練、可回放的閉環。

---

## 1. 問題重述：為什麼「更會推理」仍然不夠

近年大型語言模型的能力提升，主要沿著幾條路線發展：

1. **Chain-of-thought / reasoning trace**：讓模型顯式生成中間推理。
2. **Reasoning + acting**：讓模型在推理過程中呼叫工具或與環境互動，例如 ReAct。
3. **Tool use**：讓模型學會何時、如何呼叫 API，例如 Toolformer。
4. **Test-time search**：在推理時展開多條路徑，例如 Tree of Thoughts、Graph of Thoughts、Language Agent Tree Search。
5. **Reflection / self-improvement**：讓模型從錯誤、feedback 或過去 episode 中改進，例如 Reflexion、Self-Refine。
6. **Memory / context management**：讓模型透過記憶層、工作集與上下文管理支持長任務，例如 MemGPT、Generative Agents、Voyager。
7. **Agent safety / evaluation**：將 agent 的風險從文本輸出擴展到行動層、安全性、魯棒性與風險意識。

這些方向都重要，但若只是把它們以外部 workflow 拼起來，會出現幾個根本問題：

- 推理與行動之間沒有正式語義邊界。
- 工具呼叫常成為硬編排流程，而不是 learned policy。
- search / planning 常是外部演算法，不是智能體內部可歸因能力。
- memory 可能退化成 retrieval cache，而非可治理的長期狀態。
- verification 常只在最終答案發生，而不是 action-level runtime service。
- side effects 缺乏 transaction semantics，難以回放、回退、審計。
- failure 只能被觀察為「錯了」，無法細分成 representation、procedure、search、memory、abstraction、evaluation 或 execution governance 失敗。

因此，本文件提出的核心問題是：

> **如何設計一個不是 tool-first、不是 workflow-first、不是 search-first，而是以 learned cognition 為核心，同時具備可執行推理、可驗證行動、可管理 context、可審計 side effects 與可恢復失敗路徑的智能體 runtime？**

## 2. 研究脈絡與吸收原則

本節不是文獻綜述，而是將相關研究轉化為設計原則。

### 2.1 ReAct：推理與行動必須交錯，而不是前後分離

ReAct 的核心價值在於把 reasoning trace 與 task-specific actions 交錯生成，使模型可以在推理過程中查詢外部資訊、更新計畫、處理 exception，而不是先一次性想完再行動。

**吸收原則：**

- 智能體不應把 reasoning 和 acting 當成兩個獨立階段。
- 行動結果必須回流到 reasoning state。
- 觀察、行動、推理更新應形成連續閉環。
- 每個 action 都應有可追蹤的 state transition 與 verifier evidence。

**本文件中的對應設計：**

```text
Hypothesis -> Action Proposal -> Observation -> State Update -> Verification
```

ReAct 證明了 reasoning/action 交錯比單純推理或單純行動更有彈性；但本設計進一步要求 action 被 transaction 化、evidence 化、credit-addressable 化。

### 2.2 Toolformer：工具使用應是模型學到的決策，而不是外部流程圖

Toolformer 的核心貢獻是讓語言模型學會「何時呼叫 API、呼叫什麼、傳什麼參數、如何把結果納入後續預測」。

**吸收原則：**

- 工具不是智能本體，而是外部 substrate。
- 工具使用的時機、參數與結果融合應由 learned control 決定。
- 工具結果不得繞過核心狀態表示，形成 private side-channel。
- 工具不能成為 oracle；其結果仍需驗證與 provenance tracking。

**本文件中的對應設計：**

工具呼叫被放入 Execution IR / Episode Step，由 verifier 與 evidence packet 管理，而不是由手寫 if-else workflow 控制。

### 2.3 Tree / Graph / Language Agent Tree Search：推理需要可搜尋結構，但 search 不能取代智能

Tree of Thoughts 將推理單位從 token 擴展為「thought」並允許 branch、evaluate、backtrack。Graph of Thoughts 進一步將 thought 組成任意圖結構。Language Agent Tree Search 則把 reasoning、acting、planning 與 environment feedback 放入 tree search / MCTS-style 框架。

**吸收原則：**

- 智能體需要 branch、lookahead、rollback、candidate evaluation。
- Search 是認知控制的一種外顯形式，但不能成為唯一解題核心。
- 搜尋節點必須攜帶 state、action、evidence、credit metadata。
- 搜尋展開與停止條件應由 learned budget / termination policy 控制，而不是固定深度或固定 beam。

**本文件中的對應設計：**

```text
Branch = State Summary + Candidate Action + Expected Effect + Evidence Slot + Credit Hints
```

因此 search 不再只是 prompting trick，而是被納入 Execution IR 與 Episode Governance。

### 2.4 Reflexion / Self-Refine：feedback 是語義梯度，但不能只存在 prompt 裡

Reflexion 顯示 agent 可將環境回饋轉成 verbal reflection，寫入 episodic memory，改善後續 trial。Self-Refine 則顯示同一模型可以生成初稿、提出 feedback、再迭代修正。

**吸收原則：**

- Feedback 應成為系統內部的可消費訊號，而不是只被拼進 prompt。
- Reflection 應與 failure taxonomy、credit routing、recovery action 對齊。
- 自我修正不能只是「再試一次」，而應指定哪個能力面需要修復。
- Reflection memory 需要 write gate，避免污染長期記憶。

**本文件中的對應設計：**

Reflection 被重新定義為：

```text
Failure Evidence -> Credit Routing -> Targeted Recovery -> Memory Write / Suppress
```

### 2.5 Voyager / Generative Agents：長期能力來自 skill、memory、reflection 的複合結構

Voyager 展示了自動 curriculum、技能庫、environment feedback、自我驗證與可組合 executable skills 對 open-ended embodied agents 的重要性。Generative Agents 則展示 observation、memory、reflection、planning 如何支撐長期互動行為。

**吸收原則：**

- 智能體需要技能累積，但 skill library 不能成為第二大腦。
- 記憶需要分層：episodic、semantic、procedural、working set。
- 反思與計畫要被 memory governance 管理，而不是無限制追加。
- skill reuse 必須有 applicability check 與 verification，不可盲目套用。

**本文件中的對應設計：**

```text
Skill / Memory Item = Content + Applicability Conditions + Provenance + Validity History + Failure Profile
```

### 2.6 MemGPT：context 是作業系統問題，不只是 prompt 長度問題

MemGPT 把有限 context window 類比為作業系統中的 fast memory，並透過 virtual context management 在不同記憶層之間移動資訊。

**吸收原則：**

- Context window 不是記憶本體，而是工作集。
- 智能體需要 Context OS / Working Set Compiler。
- 壓縮、換入、換出、pinning、eviction 都是 agent runtime 的核心問題。
- Context selection 應考慮 provenance、任務階段、branch、可回放性與 verifier 需求。

**本文件中的對應設計：**

```text
Working Set = Active Goal + Current State + Relevant Memory + Evidence + Constraints + Recovery Context
```

### 2.7 LLMCompiler：多工具執行需要 dependency graph，而不是線性 call chain

LLMCompiler 顯示多 function calling 可以被編譯成帶依賴的任務圖，並在可並行時降低 latency / cost。

**吸收原則：**

- 多 action / tool call 不應只有線性序列。
- Execution plan 應顯式表示依賴、可並行性、precondition、postcondition。
- Planner、dispatcher、executor 的責任必須分離，但語義決策不能外包給硬流程。
- Execution graph 應與 verification / evidence / rollback 對齊。

**本文件中的對應設計：**

Execution IR 應支持：

```text
node: action
edge: dependency / causal precondition / evidence dependency
commit group: atomic boundary
rollback group: recovery boundary
```

### 2.8 Agent Safety / Evaluation：agent 風險不只在文本，而在行動

Agent-SafetyBench 等研究指出，agent 進入互動環境與工具使用後，風險不再只是 harmful text，而包含 unsafe action、缺乏風險意識、缺乏魯棒性、錯誤工具使用與環境副作用。

**吸收原則：**

- 安全性不應只是 output filter，而應進入 action precheck / postcheck。
- risk awareness 應是 verifier / controller 的一部分。
- 對外部 side effect 的 action 必須具備 commit / abort / rollback 語義。
- 評估不應只看 task success，也要看 unsafe action、false accept、false reject、recovery quality。

## 3. 核心設計理論

### 3.1 智能體不是模型，而是 runtime 化的閉環

本文件將智能體定義為：

```text
Agent = Cognition Kernel
      + State Representation
      + Execution Substrate
      + Context OS
      + Verifier Runtime
      + Memory Governance
      + Failure Recovery
      + Episode Governance
```

其中模型是 cognition kernel 的主要承載者，但智能行為來自整個閉環。

### 3.2 智能體的能力分解

| 能力面 | 問題 | 主要機制 |
| --- | --- | --- |
| 表徵 | 世界、任務、目標如何被內部表示？ | Canonical State Representation |
| 推理 | 如何形成、更新、比較假設？ | Recurrent Cognition Kernel |
| 規劃 | 如何產生可執行候選行動？ | Procedure / Plan Proposal |
| 行動 | 如何與工具或環境互動？ | Execution IR |
| 觀察 | 如何吸收外部回饋？ | Observation -> State Update |
| 驗證 | 如何判斷行動或答案是否可靠？ | Verifier Runtime + Evidence Packet |
| 記憶 | 如何保存、讀取、壓縮與遺忘？ | Context OS + Memory Hierarchy |
| 恢復 | 失敗後如何定位與修正？ | Credit Routing + Targeted Recovery |
| 治理 | side effects 如何提交、回退、審計？ | Episode Journal |

## 4. 三層架構

### 4.1 Layer A：核心認知核

核心認知核是智能體的唯一高容量語義主體。它負責：

- state encoding / update
- hypothesis formation
- local / recurrent reasoning
- uncertainty estimation
- budget and halting signals
- failure credit hints
- verifier feature production
- memory / tool / execution request proposal

**設計原則：**

1. 不能引入第二個高容量語義大腦。
2. 工具、記憶、檢索、planner 都不能取代 cognition kernel。
3. 控制訊號必須可學、可觀測、可校準。
4. 每次重大狀態轉移都應能被 attribution system 追蹤。

### 4.2 Layer B：行動執行基底

行動執行基底負責把 cognition kernel 的 hypothesis / plan 投影為可執行結構。

它包括：

- Execution IR
- action schema
- branch graph
- tool / environment adapter
- precondition checker
- postcondition checker
- evidence attachment point
- commit / abort / rollback logic

**設計原則：**

1. Execution IR 不等於 reasoning state。
2. Tool output 不得直接成為核心語義狀態，必須經過 observation normalization。
3. 每個 action 都需要 provenance。
4. 任何有外部副作用的 action 都必須有 commit discipline。

### 4.3 Layer C：Context 與 Runtime Governance

這一層負責長時程穩定性。

它包括：

- working set compiler
- memory hierarchy
- retrieval provenance
- compression / summarization
- context pinning
- evidence retention
- episode journal
- runtime manifest
- replay / reconciliation

**設計原則：**

1. Context 是工作集，不是越多越好。
2. Memory 是受治理的狀態，不是無限制追加的 log。
3. 長任務必須能重建關鍵決策路徑。
4. 失敗與恢復必須能定位到具體 episode step。

## 5. 第一級系統原語

### 5.1 Canonical State Representation

智能體需要一個跨模組共享的 canonical state，用來表示：

- task intent
- global context
- objects / entities
- relations
- events / transitions
- abstractions / macros
- confidence / uncertainty summaries
- verifier-relevant state

State representation 的目的不是讓人閱讀，而是讓系統維持跨模組一致性與可歸因性。

**邊界規則：**

- State representation 是 reasoning state。
- Execution plan、tool trace、raw memory document 不應直接混入 reasoning state。
- 外部資訊必須經過 normalized observation 或 summary projection。

### 5.2 Execution IR

Execution IR 是行動語義，不是推理語義。

它表示：

```text
ExecutionStep {
  step_id
  parent_step_id
  action_type
  action_payload
  expected_effect
  preconditions
  postconditions
  dependency_edges
  verifier_requirements
  rollback_policy
  side_effect_class
}
```

**核心用途：**

- plan compilation
- tool dispatch
- branch management
- execution replay
- side-effect governance
- evidence alignment
- recovery diagnosis

### 5.3 Evidence Packet

Evidence Packet 是每個重要 action / branch / verifier event 的標準證據單位。

```text
EvidencePacket {
  evidence_id
  episode_id
  step_id
  pre_state_summary
  action_ref
  observation
  post_state_summary
  verifier_result
  confidence
  disagreement
  violated_constraints
  failure_logits
  credit_hints
  provenance
  runtime_context
}
```

**設計原則：**

- Evidence Packet 不是 explanation。
- Evidence Packet 是 verifier、credit router、recovery policy、regression harness 的共同材料。
- Evidence Packet 必須能支持 rollback diagnosis。

### 5.4 Context OS / Working Set Compiler

Context OS 負責把長期資訊編譯成當前推理所需的 working set。

```text
WorkingSet {
  active_goal
  current_state
  pinned_constraints
  relevant_memory
  branch_context
  evidence_context
  recovery_context
  tool_context
  provenance_index
}
```

**核心操作：**

- retrieve
- rank
- compress
- pin
- evict
- summarize
- reconstruct
- branch-specific pack
- provenance-preserving pack

### 5.5 Episode Journal

Episode Journal 是智能體行為的 transaction log。

```text
EpisodeStepStatus =
  PROPOSED
  PENDING
  APPLIED
  ABORTED
  ROLLED_BACK
  RECONCILED
```

它記錄：

- step identity
- state hash
- action identity
- evidence identity
- verifier result
- commit status
- rollback status
- runtime / tool provenance
- memory write effects

**核心目的：**

- exactly-once semantics
- replay
- audit
- crash recovery
- failure localization
- safety review

## 6. 核心閉環

### 6.1 基本閉環

```text
1. Encode external input into canonical state
2. Form hypothesis
3. Propose candidate plan / action
4. Compile action into Execution IR
5. Pre-verify action safety and feasibility
6. Execute or simulate
7. Collect observation
8. Build Evidence Packet
9. Verify postcondition
10. Commit, abort, retry, or rollback
11. Update memory / context
12. Emit output, confidence, credit, audit artifact
```

### 6.2 失敗閉環

```text
failure detected
  -> collect evidence
  -> assign failure credit
  -> choose recovery target
  -> apply targeted recovery
  -> re-verify
  -> update memory only if write gate accepts
```

**禁止模式：**

- 錯了就整條 pipeline 重跑。
- 錯了就增加 search depth。
- 錯了就把所有內容塞進 context。
- 錯了就降低 verifier 門檻。
- 錯了就無條件寫入反思記憶。

## 7. Failure Taxonomy 與 Credit Routing

### 7.1 Failure 類型

| Code | 類型 | 智能體語義 |
| --- | --- | --- |
| F_REP | Representation Failure | 狀態表徵錯、漏、碎裂或不一致 |
| F_PROC | Procedural Failure | procedure / plan / action schema 錯 |
| F_SEARCH | Search / Budget Failure | 分支、資源、停止、探索策略錯 |
| F_MEM | Memory Failure | 讀錯、漏讀、寫壞、污染或 stale memory |
| F_ABS | Abstraction Failure | 抽象粒度錯、壓縮錯、macro 誤用 |
| F_EVAL | Evaluation Failure | verifier、confidence、calibration、risk judgment 錯 |
| F_EXEC | Execution Governance Failure | action side effect、commit、rollback、replay、tool provenance 錯 |

> 註：`F_EXEC` 是本文件為 agent runtime 新增的研究假設。若要納入正式規格，應以 Change Proposal 處理，不應直接改動既有 taxonomy。

### 7.2 Credit Vector

```text
failure.credit = {
  representation,
  procedure,
  search_control,
  memory_context,
  abstraction,
  evaluation,
  execution_governance
}
```

Credit routing 的目的不是產生人類解釋，而是決定：

- 要重做哪一層
- 要增加哪種 evidence
- 要不要擴展 search
- 要不要重編譯 context
- 要不要壓制 memory write
- 要不要 rollback
- 訓練時 loss / feedback 應路由到哪個能力面

### 7.3 Targeted Recovery

| Failure | Recovery |
| --- | --- |
| F_REP | 重新 normalize observation、重建 object/relation/event state |
| F_PROC | 重新 proposal、調整 action schema、重排 procedure |
| F_SEARCH | 延後停止、重新分支、調整 budget、提高 verifier escalation |
| F_MEM | 重新 retrieval、降低 stale memory 權重、禁止污染寫入 |
| F_ABS | 調整 compression granularity、禁用過強 macro |
| F_EVAL | 更嚴 verifier、校準 confidence、要求更多 evidence |
| F_EXEC | abort / rollback / reconcile、重建 action provenance、檢查 side effect |

## 8. 記憶理論：Memory 不是資料庫，而是受治理的行為資產

### 8.1 四層記憶

| 記憶層 | 內容 | 風險 |
| --- | --- | --- |
| Working Memory | 當前任務必須資訊 | context overstuffing |
| Episodic Memory | 過去 episode、action、evidence | stale episode reuse |
| Semantic Memory | 抽象知識、規則、概念 | overgeneralization |
| Procedural Memory | skills、action schemas、routines | skill misapplication |

### 8.2 Memory Item Schema

```text
MemoryItem {
  id
  type
  content
  embedding
  provenance
  creation_episode
  applicability_conditions
  success_history
  failure_profile
  freshness
  compression_level
  write_gate_score
}
```

### 8.3 Memory Write Gate

記憶寫入必須有 gate。寫入條件至少考慮：

- evidence quality
- verifier confidence
- recurrence value
- novelty
- failure risk
- provenance completeness
- 是否來自 rollback / failed episode
- 是否可能污染 future retrieval

## 9. Context OS 理論

### 9.1 Context 不是 buffer

Context 應視為：

```text
Context = compiled working set for current control state
```

而不是：

```text
Context = everything possibly useful
```

### 9.2 Working Set 編譯準則

| 問題 | 決策 |
| --- | --- |
| 必須存在？ | pin |
| 可壓縮？ | summarize |
| 可重建？ | store pointer |
| 需要 verifier？ | retain evidence |
| branch-specific？ | isolate by branch |
| provenance-critical？ | preserve source |
| stale risk? | decay or demote |

### 9.3 Context Failure

常見 context failure：

- irrelevant context overload
- missing critical evidence
- stale memory reuse
- compressed away constraints
- branch contamination
- unverifiable summary
- lost provenance

這些不應只被視為 prompt engineering 問題，而應進入 failure taxonomy 與 regression metrics。

---

## 10. Verification 理論：Verifier 是 runtime service

### 10.1 Verifier 不只是最後裁判

Verifier 應覆蓋：

- pre-action feasibility
- pre-action safety
- post-action validity
- branch consistency
- evidence sufficiency
- memory write safety
- rollback legitimacy
- final answer correctness

### 10.2 Verifier Output

```text
VerifierOutput {
  validity_score
  confidence
  calibration_state
  disagreement
  risk_score
  violated_constraints
  required_extra_evidence
  failure_logits
  credit_hints
}
```

### 10.3 False Accept 比 False Reject 更危險

在 agent runtime 中，false accept 不只是答錯，而可能導致：

- 錯誤 tool action 被提交
- 錯誤 memory 被寫入
- 錯誤 side effect 無法回復
- 錯誤 branch 被當成成功路徑

因此 verifier 的主要設計目標不應只是提高 task success，而是降低 unsafe / invalid commit。

## 11. Execution Governance

### 11.1 Action Side Effect Classes

| Class | 說明 | Governance |
| --- | --- | --- |
| READ_ONLY | 查詢、觀察 | provenance required |
| SIMULATED | 模擬執行 | evidence required |
| REVERSIBLE | 可回退變更 | rollback policy required |
| COMMITTABLE | 需要提交的變更 | pre/post verification required |
| IRREVERSIBLE | 不可逆外部影響 | explicit escalation required |
| MEMORY_WRITE | 內部記憶更新 | write gate + provenance required |

### 11.2 Commit Protocol

```text
PROPOSED
  -> PRECHECKED
  -> PENDING
  -> EXECUTED
  -> EVIDENCED
  -> VERIFIED
  -> APPLIED
```

失敗路徑：

```text
PENDING / EXECUTED
  -> ABORTED
  -> ROLLED_BACK
  -> RECONCILED
```

### 11.3 Replay-Safe Principle

任何可重放的 episode 必須保存：

- action input
- environment/tool version
- runtime manifest
- state hash
- evidence packet
- verifier result
- commit status
- memory write effects

---

## 12. 學習與訓練方向

### 12.1 Pretraining 不是只學知識，而是學 process

智能體訓練應避免只優化 final answer。核心訓練信號應包括：

- representation consistency
- plan/action proposal quality
- verifier calibration
- evidence sufficiency
- recovery correctness
- memory write discipline
- context compilation quality
- rollback / commit correctness
- failure credit stability

### 12.2 Synthetic Data 方向

合成資料可支援以下能力：

| Synthetic Task | 目標 |
| --- | --- |
| Delayed Credit Tasks | 讓錯誤延後顯現，訓練 credit routing |
| Recovery Tasks | 讓模型學會 targeted retry，而非 blind retry |
| Context Compilation Tasks | 在有限 context 中選擇必要證據 |
| Evidence Sufficiency Tasks | 判斷何時證據不足 |
| Transaction Tasks | 訓練 commit / abort / rollback |
| Memory Pollution Tasks | 判斷何時不應寫入記憶 |
| Branch Consistency Tasks | 維持多分支狀態隔離 |
| Tool Provenance Tasks | 識別工具輸出可靠性與版本差異 |

### 12.3 Runtime Feedback as Training Signal

Agent runtime 可產生高價值 training traces：

```text
(state, action, evidence, verifier, credit, recovery, outcome)
```

但必須過濾：

- verifier unreliable traces
- tool failure traces
- context polluted traces
- ungrounded reflection traces
- unsafe action traces
- rollback-unresolved traces

## 13. 評估理論

### 13.1 Outcome 是次要指標

智能體的主要評估不應只看 task success，而應看 process integrity。

### 13.2 Primary Metrics

| Metric | 目的 |
| --- | --- |
| reasoning_to_action_fidelity | hypothesis 是否正確轉成 action |
| evidence_sufficiency_score | evidence 是否足以支持 commit |
| verifier_false_accept_rate | invalid action / answer 是否被接受 |
| verifier_false_reject_rate | valid path 是否被錯拒 |
| credit_routing_entropy | failure attribution 是否退化 |
| targeted_recovery_success | recovery 是否修對層 |
| context_relevance_ratio | working set 是否有效 |
| context_provenance_loss | context 是否失去來源 |
| memory_pollution_rate | 錯誤記憶寫入率 |
| rollback_success_rate | 回退是否可靠 |
| replay_consistency | replay 是否得到一致狀態 |
| unsafe_action_rate | 不安全行動比例 |
| commit_integrity_score | commit 是否符合 pre/post condition |

### 13.3 Regression Philosophy

若 task success 上升，但以下任一項退化，應視為 regression：

- credit routing collapse
- verifier calibration degradation
- concept / context leakage increase
- memory pollution increase
- false accept increase
- unsafe action increase
- replay inconsistency
- rollback failure increase
- hard-coded control replacement of learned policy

## 14. 與主流 agent 架構的差異

| 主流方向 | 常見問題 | 本設計的修正 |
| --- | --- | --- |
| Tool-first agent | 工具成為 intelligence locus | 工具只是 execution substrate |
| Prompt workflow agent | 流程不可學、不可歸因 | learned control + credit routing |
| Search-heavy agent | search 掩蓋 representation failure | search 受 budget policy 與 failure attribution 約束 |
| Memory-heavy agent | retrieval 取代理解 | memory read/write gated and verified |
| Reflection agent | 反思污染 context | reflection 需 evidence + write gate |
| Planner-executor | executor 成為外部語義權威 | execution effects must be verified and projected |
| Long-context agent | context stuffing | working set compiler |
| Benchmark-optimized agent | 為測試集塑形 | benchmark only as probe |

## 15. 分階段路線圖

### Stage 0：概念邊界鎖定

交付物：

- State vs Execution boundary note
- Evidence Packet sketch
- Episode Journal sketch
- Failure taxonomy extension proposal
- Context OS design note

完成標準：

- 不再混淆 reasoning state 與 execution trace。
- 不再把 tool log 當成 state。
- 不再把 memory append 當成 learning。

### Stage 1：最小閉環原型

目標：

```text
state -> plan -> action -> evidence -> verify -> commit / abort
```

限制：

- 封閉 toy environment
- 無不可逆 side effect
- 所有 action 可 replay
- verifier simple but explicit
- episode journal complete

### Stage 2：Targeted Recovery

加入：

- failure classification
- credit vector
- recovery action selection
- re-verification
- recovery trace logging

完成標準：

- 系統能區分「表徵錯」、「計畫錯」、「驗證錯」、「記憶錯」。
- 不再以盲目 retry 作為主要 recovery。

### Stage 3：Context OS

加入：

- working set compiler
- memory tiers
- retrieval provenance
- compression policy
- context regression metrics

完成標準：

- 長 episode 中 context relevance 上升。
- provenance loss 下降。
- stale memory reuse 下降。

### Stage 4：Execution Governance

加入：

- commit protocol
- rollback protocol
- replay tests
- runtime manifest
- side-effect classification

完成標準：

- episode 可 replay。
- action 可 audit。
- rollback 可驗證。

### Stage 5：單一垂直場景壓測

選擇一個高價值場景，例如：

- code repair agent
- research assistant agent
- tool-using data analysis agent
- controlled robotics / simulation agent
- document operations agent

評估：

- task success
- evidence quality
- recovery quality
- context scaling
- memory pollution
- replay consistency
- unsafe action rate

## 16. 主要風險

### 16.1 False Agentic Progress

系統看起來更像 agent，但實際只是：

- 更多 prompt choreography
- 更多 hard-coded retries
- 更多 tool calls
- 更多 context stuffing
- 更少 learned control

**防範：**

- 所有 control 必須可觀測、可訓練、可歸因。
- tool use 必須由 learned policy 控制。
- hard-coded policy 只能是 technical debt guardrail。

### 16.2 Execution IR 變成第二套語義狀態

若 Execution IR 開始承載 reasoning state，會造成 state drift。

**防範：**

- Execution IR 只描述 action / dependency / commit / rollback。
- Reasoning state 必須回到 canonical state representation。
- Execution result 必須透過 observation / evidence projection 回流。

### 16.3 Memory 污染

錯誤 reflection、錯誤 tool result 或 failed episode 被寫入長期 memory。

**防範：**

- memory write gate
- verifier confidence threshold
- provenance requirement
- failed trace quarantine
- stale memory decay

### 16.4 Verifier 過度自信

Verifier false accept 導致錯誤 action commit。

**防範：**

- verifier disagreement
- calibration tracking
- evidence sufficiency score
- high-risk action escalation
- commit-time recheck

### 16.5 Governance 過重

過多 journal / manifest / evidence overhead 阻礙研究速度。

**防範：**

- phase-based activation
- toy environment first
- minimal schema first
- only govern side-effectful operations initially

## 17. 研究假設

### H1：Reasoning-to-action fidelity 是 agent 能力的核心瓶頸

若模型能推理但行動轉譯不穩，agent 仍不可用。

### H2：Evidence Packet 能顯著提升 verifier reliability

將 verifier 從 final-answer judge 變成 evidence-consuming runtime service，可降低 false accept。

### H3：Context OS 比單純增加 context window 更重要

在長任務中，working set quality 比 context 長度更直接影響穩定性。

### H4：Failure credit routing 能改善 recovery efficiency

Targeted recovery 比 blind retry 更省成本、更少污染記憶、更可解釋。

### H5：Episode governance 是 agent 安全性的核心基礎

對 side effects 沒有 commit / rollback / replay 語義的 agent，難以可靠部署。

## 18. 最終設計宣言

本設計主張：

> 下一代智能體的核心不是「更長的推理鏈」或「更多工具呼叫」，而是把推理、行動、證據、驗證、記憶、提交、回退與恢復組成一個可學習、可觀測、可審計、可回放的閉環。

它應該避免以下退化：

- 不是 tool-first dispatcher
- 不是 symbolic executor wrapper
- 不是 prompt workflow
- 不是 search-only planner
- 不是 memory retrieval system
- 不是 benchmark-shaped system
- 不是工程 patchwork

它應該成為：

```text
Cognition-centered
Execution-aware
Evidence-grounded
Context-governed
Memory-disciplined
Failure-attributable
Replay-safe
Learnable-control-first
```
