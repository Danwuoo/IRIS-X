2. Freeze E20 operator/depth/node/time/memory configuration before one CPU dev
   execution. Reject the configuration if it has no correct dev candidate or
   no complementary coverage; do not deepen search or add answer-specific rules

   dependency checks, current free quota, current provider rules and hardware,

   140 test runs. The first six interleaved control tasks are included in this

   sequence cap, 20/30-second nominal generation/verification allocation and
   shared parent watchdog. Only verification schedule differs. Maximum screen

   This is a planning maximum, not measured throughput or quota permission.
   Exact forward/token bounds are derived from frozen 24/35 task material.
5. Compare E12 64/128 TTT and E11 DFS 0.2/0.1 only after E10 calibration works,
   one factor at a time, retaining the same 24 development tasks. Their exact
   finite token/session/quota admissions must be frozen before launch. E12
   keeps the 128-step scheduler horizon and sampler prefix. Reject cost saving
   below 25 percent or demonstrable candidate loss. Reject E11 earlier cap
   exhaustion without oracle improvement.
6. E21/E22/E30 are conditional on measured unresolved coverage and deployment
   feasibility. E40 training is conditional on small-experiment support and
   licenses. The backlog is not permission for unlimited model search, paid
   teachers, changing thresholds or using private answers.
7. Freeze the final supported configuration, run the single isolated public
   confirmation comparison, and measure a complete private deployment/resource
   rehearsal. Package E90 and stop before official competition submission.

An inconclusive or negative experiment remains retained evidence. It does not
authorize best-seed selection, discarded failures, or a wider post-hoc search.
Routine code/transport repair may continue with new immutable identities after
the failure is diagnosed; failed scientific hypotheses are not rerun unchanged.
Quota is re-observed before admission and no paid scaling may be enabled.
