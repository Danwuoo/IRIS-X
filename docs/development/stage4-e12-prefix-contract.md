# E12 prefix stopping: inert CPU contract

The new E12 profile changes only the stopping update: 64 versus 128. Both runs
start independently from the same model, empty optimizer/gradients, and all RNG
streams. Both prepare all 128 source rows, retain the same full sampler order,
and use the original 128-step cosine horizon and 13-step warmup. The 64 profile
is a new scientific profile, not original full-epoch native parity.

`tools/nvarc_e12_prefix_contract.py` contains a closed contract, an observable
Trainer event controller, direct trace validation, paired-prefix validation, and
a separate complete-session cost validator. `tools/nvarc_e12_prefix_fixture.py`
provides a deterministic fake Trainer and exportable positive fixture. These
files import no ML libraries and contain no provider, native runner, publication,
or admission path. Synthetic contract and trace labels explicitly say CPU
synthetic only. The separate `build_native_contract` path accepts native
observations only with a closed source-verified scalar-schedule receipt and
the pinned reference rates; its declarative contract remains INERT and grants
no execution/publication permission. Neither path by itself qualifies the
full native runtime.
Historical E10/E11 modules, admission policies and full-epoch APIs are unchanged.

## What the CPU proof checks

- Trainer arguments remain `max_steps=-1`, one epoch, batch size one and gradient
  accumulation one; the derived state retains `max_steps=128`. Setting either
  horizon to 64, truncating the dataset, or recomputing seven-step warmup fails.
- The contract binds 128 prepared row digests and the complete sampler
  permutation. Actual input IDs and labels are hashed at step entry and compared
  with that ordered prefix. A multiset match or a freshly shuffled 64-row dataset
  cannot substitute. Token counts use the same shifted-label convention as the
  native budget. No test output, answer label or solution is accepted.
- Each row needs one returned finite forward, completed backward, actual
  optimizer entry and return, then scheduler return and the post-update callback.
  Every one of 506 Adam parameter counters must advance from i to i+1. The first
  optimizer call has LR zero and still advances moments; unchanged weights at
  that call are not evidence of a skipped update.
- Update 64 consumes LR index 63. Its scheduler finishes at index 64 before the
  callback requests stopping. The next forward is prohibited even if a trainer
  ignores the stop request. The control must complete all 128 updates and epoch
  one. Rejected actions, early stops, unknown counters, backward/optimizer
  exceptions, and nonfinite loss cannot recover into a qualified trace.
- Model inventory, empty optimizer/gradients and Python, NumPy, CPU Torch and
  CUDA RNG digests bind each entry and final reset. The paired validator compares
  first 64 row/update/LR/RNG records. Synthetic pairs also require identical
  losses. Native pairs retain finite losses and report their numerical equality
  and maximum absolute difference; equal losses are not a gate for separately
  reset CUDA runs. A difference overflowing finite JSON arithmetic is explicitly
  reported with a null maximum and an overflow flag. Synthetic dropout is
  generated by separately seeded scalar fakes, not a CUDA simulation.
- Actual inference budgets are represented by one exact source-contract digest;
  any change between arms changes the binding. Saved training time is never
  reallocated to inference. The controller does not itself run inference.

The mathematical scalar fixture is checked against the retained E11 native
reference within the original four-ULP portability tolerance. That is not an
attestation that native scheduler code ran. A real adapter must still obtain
the worker's actual same-platform rates with the existing source-verified
`native_schedule`, retain its receipt, and compare optimizer groups exactly
against those rates. New E12 native admission must make this distinction
explicit rather than relabeling the CPU receipt as native proof. Native
contracts retain the receipt's exact observed rates, which may differ from
the reference by up to four ULPs. Optimizer group checks remain exact against
the observed rates; there is no optimizer tolerance.

## Native integration still required

1. Bind the new package to the exact existing model/configuration, challenge
   projection, dependency source/wheel material, Trainer origins and source
   preparation evidence. Do not import returned code or read evaluator truth.
2. Observe the original Trainer sampler over its full prepared dataset, with
   its original generator/seeding and RNG side effects. Retain all 128 indices
   and verify both arms' actual row sequence. A new sequential sampler, a
   64-item sampler or an offline guessed permutation would change the method.
   Duplicate token-identical rows cannot establish distinct sampler indices
   from token hashes alone; sampler-level index evidence is required.
3. Install actual forward and successful training-step/backward hooks, AdamW
   construction/recipe/parameter checks, pre/post optimizer moment inspections,
   scheduler observations and a real `TrainerCallback` subclass. Keep original
   clipping, gradients, finite moments, checkpoint flags, dtype/device, tensor
   inventories, preparation zero-work guards and deadline accounting. Native
   imports must occur only after separate runtime admission. The CPU controller
   is not itself that subclass and does not verify gradient/moment tensor bytes.
4. Capture and restore actual model, Python/NumPy/Torch/CUDA RNG state and fresh
   optimizer, accelerator and scheduler objects for each arm. No momentum or
   dropout stream may carry over from the short arm. Confirm real callback
   ordering, derived epoch fraction, no skipped AMP updates, and no step65.
   Finite native loss differences are retained diagnostics, without a numerical
   equality or causal-performance claim. Nonfinite losses or any source/RNG/LR/
   update mismatch still reject prefix qualification. No equality of the final
   64-update and 128-update trained model states is required or implied.
5. Run each arm's unchanged inference with fresh counters/cache/adapter and the
   same p=.2 interleaved recipe, full per-test windows and all existing forward,
   token, candidate and truth-free return limits. Retain trained-state results
   before final reset, then verify full model/reset/cache controls.
6. Add bounded supervisor, cleanup, finalizer, exact archive membership,
   independent replay and package admission. Measure host observation,
   inventory/RNG digesting, synchronization, ledger IO and checkpoint overhead;
   include them in the same deadlines and observed costs. Host timers are not
   GPU kernel duration or lease-time proof.

The declared source digests in synthetic fixtures are labeled synthetic and
cannot satisfy any real material gate. The worker integration must preserve a
distinct native evidence envelope, not turn these declarative contracts into
execution authorization.

## Resource and experiment boundaries

`research/stage4-e12/inert-prefix-plan.json` preserves the original screen:
24 development tasks / 35 tests, two arms, two technical repeats: 96 task-runs,
9,216 optimizer updates and 140 arm-test evaluations. Technical repeats do not
increase the 24 independent task clusters. Screen gates remain at least 25%
total allocated-GPU cost reduction, no more than one lost pass@2 test and one
lost oracle test, and no reset failure. Locked confirmation remains closed and
shared across Stage4. BASE0 is reference-only if exact source/config matches;
otherwise it requires separate authorization.

A four-task/six-test engineering pilot is separately proposed: 8 task-runs,
768 updates and 12 arm-test evaluations, one technical repeat. It establishes
mechanism and runtime evidence only. It cannot replace the full screen or open
confirmation. No quality or cost acceptance is inferred from that pilot.

The planning-only 60-minute pilot envelope is 900 seconds startup, 1,200
seconds combined 64+128 training, 600 seconds both-arm inference, 360 seconds
for two resets, 300 seconds finalization, and 240 seconds margin. This sum is
arithmetic, not measured feasibility; all guards and overhead consume it.
Four L4 allocations reserve at most four GPU-hours. The parent observed
3.195315 remaining free GPU-hours at 2026-10-07 14:55 UTC, which is less than
that ceiling; this is historical context, not a current quota attestation.
No 45-minute feasibility or scope reduction follows. Any future provider
decision needs a fresh exact-package/quota check by the coordinating thread.

Separately reset runs are preferred over sharing a step64 snapshot and
continuing to128. Shared continuation would be a different common-trajectory
design and cannot supply the cost of an independent64 run. Likewise, if both
arms share one pilot notebook lease, their task-worker/training timers are
proxies. A session-wide total cannot be split into independently observed arm
costs by subtracting startup or dividing shared time. The complete cost gate
needs identical allocation/meter definitions and observed entire sessions for
each arm (including startup, warmup, resets, inference, checkpointing and final
output), or a separately reviewed attribution design. Unknown total cost stays
null. Historical training fractions and linear-halving assumptions are not
used to predict E12 savings.

```sh

mkdir -p .irisx/e12-review

```

The fixture writer exclusively creates the output and refuses to replace
retained bytes. Tests cover positive paired records and counterexamples for
schedule, sampler, lifecycle, counters, reset/RNG, truth fields and total-cost
accounting. Fake tests do not establish native Trainer callback ordering,
GPU numerics, timing feasibility, accuracy or official-score readiness. The
lead runs the required full repository aggregate after integration; this lane
runs focused checks only.
