## Exact source/material boundary

The new builder uses the clean E10 code/material contract: three pinned native
code-only files, explicit helper files, exact dependency/model inventories and
small verified tokenizer. Only the original plan's named configuration fields
and 129-rate / 128-step schedule are projected; its old task specifications and
preview input are not packaged. Never give this builder the companion archive
or evaluator answer directory as its material input.

Every tracked build/runtime source must equal a full requested Git commit.
The source snapshot includes current E01 lifecycle, E10 caller transport, native
strict exporter, reviewed source loader, worker renderer and new parent/builder.
The eight existing native producer gates are retained. The assigned-GPU bridge
and finite E10 worker are explicit source transformations; old frozen bytes are
not modified. The closed package stores both original build sources and exact
runtime payload. Its notebook is compressed/base64 data, independently decoded
by AST literal extraction without executing the notebook. Preflight reconstructs
candidate, payload, notebook, metadata and CLI plan and rejects changed, extra,
foreign or symlinked files. Retain the package-manifest SHA256 independently;
self-consistent hashes alone cannot authenticate a changed package.

The default package is inert (`approved=false`). A coordinator may supply exact
byte references to its separate execution-plan, current free-resource and
rules/material review receipts. Those references are not authenticated by the
builder and do not prove quota, scientific merit or successful GPU execution.
The builder does not duplicate provider authentication or execution-ledger logic.
Any changed admission/config/code uses a new immutable identity and package path.

Scientific selection stays pending even with private execution admission.
`interleaved` is the default rehearsal configuration; either schedule can be
explicitly frozen in the policy. This is not a winner declaration. E20's rejected
0/35 development screen is not selected or included. Real E10, conditional
ablations, final selection and the one public confirmation comparison remain
coordinator-owned scientific gates.

## Full mounted input and fresh resource admission

The notebook reuses the deadline-authoritative supervisor, reserving 60 seconds
inside the whole notebook ceiling for termination/polling; silent or blocked
console output cannot bypass that clock. An unconfirmed child exit is failure.

The notebook has no embedded task IDs, challenge data, task count or test count.
The parent opens only the mounted `arc-agi_test_challenges.json`, rejects test
outputs/extra fields, derives all actual task materials and keeps every actual
test in its plan/export denominator. New IDs, ordering and multi-test tasks are
supported. All training limits, complete native epochs, source learning rates,
forward/token caps, reset and strict transcript gates remain intact.

The verified model/dependency/hardware preparation, including bounded TensorFlow
uninstall, completes before CPU material preparation. The additive shared source
verification wrapper brackets the exact source-inventory bytes, validates the
actual legacy prepare-produced digest/root receipt, preserves it separately and
retains the full inventory required by the unchanged strict native gate. This
fixes a reproduced integration schema mismatch; a self-reported digest alone
cannot replace the inventory or actual dependency byte checks. CPU material versions are
checked against the pinned dependency inventory. Only after both does allocation
use the measured monotonic remainder. Another fresh observation immediately
before caller creation/first dispatch is frozen in the runtime plan, and whole
lane reservations are checked again immediately before each process launch.
The full workload is rejected if it no longer fits; admission does not quietly
skip a selected subset. Receipts and plan retain unlaunched/failed denominators.

Four longest-processing-time lanes reserve each whole 128-step epoch, public
training-token allowance, 30 seconds for every actual test, fresh preparation
and reset. Both schedules use parent-owned E10 20/30-second caller allocations,
including session clipping. The parent retains admission maps and durably saves
a receipt before replying to the worker; exact receipt hash is passed into the
fresh seed-zero CPU strict exporter. Host clock receipts are not physical GPU
or OS attestation. Cleanup attempts all acquired streams/processes/channels,
including partial launches, and freezes caller evidence only after confirmed
producer termination. Secondary logger failures do not replace a primary error.

The default 42,600-second ceiling is an inert engineering planning envelope,
not a verified current provider limit. Preparation, scheduler and finalization
reserves are explicit. Coordinator admission must re-observe current free quota,
hardware/session limits, rules and mounts. No runtime is admitted merely because
these offline numeric estimates fit. Official hidden input feasibility is not
established by a public rehearsal.

## Output, recovery and exit

Native replay publishes an E01 immutable generation; root `submission.json` and
sidecars are projections with a separately verified projection marker. The new
parent uses current `publish_working_output` / `recover_working_output`, never
legacy `copyfile`. A stopped producer's strict zero-model native re-export is
required before working-root recovery; recovery compares exact values and reuses
the committed generation, rather than inventing another model result.

`output_valid`, `notebook_exit`, `evidence_qualified` and `promotion` are separate.
A valid root generation survives terminal/cleanup failure but cannot imply a
successful notebook exit or promotion. Post-commit projection failure is
recoverable; an invalid root projection is not called output-valid. Promotion is
always false in this engineering path. The exact production parent observes separate common-preparation, fresh strict
CPU export, native readback, working publication and final-readback durations.
The fresh CPU exporter inherits the guarded parent process group and runs
through an owner-death guarded CPU wrapper before native replay. Both the
outer whole-session kill and an abrupt owner-only death stop the replay.
Local export timeout/lost-wait faults stop the owned child using a stable
Linux pidfd where available; unknown exit status never becomes exit zero.
Owned-child wait4 supplies exporter-specific peak RSS where supported; missing
measurements remain null. Process-visible logical and allocated file bytes are
sampled with a bounded inventory, with explicit sampling/errors/scope limits.
Free working disk is rechecked after preparation, immediately before dispatch
and before fresh export. Worker CUDA allocated/reserved process highwaters are
retained without extra synchronization or device/model calls; they do not
establish a simultaneous whole-run GPU peak. Resource observations are retained
separately, including failure/timeout/unconfirmed exit. Production recovery
is explicitly unmeasured until strict re-export and working recovery actually
run. Parent peak RSS is observed after publication. Every actual mounted task is passed as an unconditional mandatory task to the
fresh strict CPU exporter. The reused calibration helper independently checks
complete native epoch/source material, exact optimizer construction/LR/token and
step closure, baseline/reset tensors, post-reset control, complete actual-test
checkpoint and host telemetry, even for an empty model-candidate pool. The parent
requires this closed full-task proof map before working-root publication. The
separate private completion gate also requires every launched process to exit
zero, all full epochs, all actual tests started and all resets/control checks
verified. A failed gate after publication
retains a valid output but fails notebook exit. A complete private production
resource/strict-export/exit rehearsal remains necessary for readiness.

The candidate has no pre-existing ZIP producer. Its notebook explicitly points
to the existing E01 working-root output and native evidence in the Files tab.
No new archive-writing, recovery or re-export stage is added for a convenience
cell. Probe/screen archive downloading follows the separately described
[standalone finalized-archive controls](nvarc-e10-runtime-screen.md#standalone-finalized-archive-download).

## Bounded synthetic large-evidence measurement

`rehearse_stage4_output_resources.py` runs the actual eager E01 publication,
readback, projection and exact-generation recovery with synthetic JSON. It
permits 1 KiB–256 MiB synthetic evidence and a finite 10–600-second cooperative
publication deadline. It measures process peak RSS, sampled process-visible file
bytes and elapsed phases. Disk sampling is not a filesystem allocated-block
peak; blocking kernel IO is not forcibly preempted by application deadlines.
It reports zero model/GPU/external calls and evidence qualification false.

The initial separate fresh process with a 64 MiB synthetic evidence payload
observed 67,112,004 evidence-JSON bytes, 281,321,472 peak RSS bytes,
134,226,349 sampled file bytes and 1.911 seconds measured publication/recovery
wall (publication 0.486 seconds; recovery 0.590 seconds). This is a bounded CPU
resource observation, not strict native transcript replay, full input scale,
power-loss durability or GPU deployment feasibility. Historical native evidence
was 661,320,886 bytes, which this test explicitly does not attest. The private
full-sized production rehearsal must measure full strict-export overhead, actual
GPU/CPU peaks, disk reserve and successful notebook exit before readiness.
