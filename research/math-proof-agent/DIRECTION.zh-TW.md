# 研究方向：以可驗證證明改善數學 AI

日期：2026-10-18。此文件是依使用者最新方向建立的新研究議程，不取代任何 ARC 原研究。來源編號見 [sources.json](sources.json)；來源支持、設計推論與實驗結果分別標示。

## 1. 主問題

**在固定模型、資料及計算條件下，命題對齊、引理分解、數學工具與可核查錯誤回饋，能否比追加獨立採樣更有效地提高完整證明率和答案正確率？**

「提高」指同題配對、固定預算後的測量，不指證明變長、LLM 自評增加、得到多數票或工具沒有報错。IMO／Putnam 是初期能力階梯。長期價值是得到可移植的數學推理與可靠性方法，而非領獎、追逐單一 leaderboard 或先宣稱能自主做研究。

## 2. 方法選擇

**主線是 inference-time proof agent；SFT／蒸餾、RL、TTT 是有條件的後續介入，不是同一輪全部啟用。**

| 機制 | 第一階段角色 | 進入下一步的證據 |
| --- | --- | --- |
| 證明生成／引理分解 | 主要模型工作；先用一個固定模型，角色可共用權重 | 區分不會構造證明與只是不會 Lean 語法 |
| 精確計算／符號工具 | 找反例、驗算局部恆等式、產生可重播證書 | 每項工具結果只能支持實際已檢查的命題與假設 |
| Lean 4＋固定 Mathlib | 可形式化子集的最終證明檢查；CPU 執行 | 固定命題、完整證明項、axiom policy 與執行隔離均合格 |
| Verifier-guided repair | 第一個主要研究變因 | 與同模型、同上限的額外獨立採樣相比，配對增益可重現 |
| SFT／蒸餾 | 有驗證的成功／修復資料，改善證明表達與工具互動 | 初始模型有可學習軌跡，資料授權、同源暴露與錯誤率可追溯 |
| RL | 對固定問題／工具介面做策略改善 | 可用獎勵可信、非全零且不易鑽漏洞；有額外 SFT／搜尋成本對照 |
| TTT | 每題臨時適應的獨立後續實驗 | 有合法題內訊息、reset 正確且不讀評估答案；需勝過額外搜尋 |

這是我們的排序，不是文獻證明最終必然如此。DeepSeek-Prover-V2、Goedel-Prover-V2 提供 decomposition／verifier feedback 的方法先例 [S01,S02]；不能把其完整訓練系統的增益歸給一個新 wrapper。

## 3. 系統最小架構

`不可變題目＋假設 → 證明草圖／待證引理 → 提案 → 工具驗證 → 有界修復 → 最終答案與證明`。

只有一個 orchestration state machine，不先疊加多代理框架。保存的是可審閱的證明步驟、引理、工具輸入輸出與來源，不要求或宣稱取得模型私有推理。建議狀態為 `proposed / checking / repair_needed / accepted / refuted / unknown / budget_exhausted`；最後的 accepted 仍必須攜帶具體 trust level。

每個 proof obligation 綁定 problem ID、原題版本、形式化命題、變數型別、定義域、假設、目標與證據 hash。模型可以建議改正疑似題目錯誤，但不能在原結果中自行改成較弱定理或添入結論本身作假設；另開一個有來源的形式化修正項目。

工作角色包含 proposer、verifier 和 refiner；角色名稱不代表三份独立專家或三個模型。LLM verifier 只提供可能的缺口和修復建議，不替代 gold evaluator。最終評估不讀 agent 的 confidence 作真值。

## 4. 核心可否證假說

**H1 — 回饋是否有用。** 在相同模型、工具及上限下，固定三次修復比追加三個獨立候選更常完成相同命題的有效證明。若只有 token／時間增加而同成本曲線沒有增益，就不保留較複雜架構。

**H2 — 可信選擇是否減少錯誤放行。** 強化 statement binding、假設和完整證明檢查，可以減少「答案看似正確、證明無效」被列為成功；同時報告放棄率與有效證明被拒比例，不以全面拒答換取零錯誤。

**H3 — 分解何時有價值。** 若直接證明已有正確全局策略但卡在可形式化子目標，分解應改善完成率；若多數分解本身錯誤或引理過強，增加引理會浪費搜尋。比較同預算全證明修復與引理修復，而非只展示成功案例。

**H4 — 學習是否補足搜尋瓶頸。** 只有當題庫外驗證過的軌跡可供訓練時，才測 SFT／蒸餾或 RL。比較固定起點及等成本強基線；不要因生成很多 proof tokens 就認定模型參與了新數學研究。

## 5. 範圍與升級決策

第一輪 R001 只完成文獻及精確證書反例研究：它檢驗 H2 的一個受限 failure mechanism，不估計 LLM 的錯誤率，也沒有驗證 H1/H3/H4。詳見結果文件。

下一輪 MATH-002 做實際 Lean worker、TPU model adapter 與小面板的 independent-sampling vs verify-repair。先實測模型能否寫有意義的候選、單題完成成本及回饋解析，再固定正式 pilot；不先建立大規模 RL infrastructure。

若題目形式化錯誤主導，先修命題對齊；若所有候選都沒有正確方向，優先改善提案／資料／模型；若候選內有正解卻無法選到，先修選擇；若形式語言 syntax 主導，先改善正式訓練／翻譯；若僅缺算術，引入精確計算即可。這些不同瓶頸不能統称「reasoning 不夠」。

研究輔助（幫人查引理、檢查手稿）與模型自主研究（提出猜想、尋找新結果）暫不列成當期交付。未來需分別定義新穎性查核、研究者評審及歸功；不能拿舊竞賽題通過代替新研究成果。
